# NiceWorker Bot

友人用サーバー向けのDiscord Bot。**ルート直下で動いている Obsidian保存Bot とは完全に別物**で、
このディレクトリだけで自己完結している（ルートの `package.json` / `src/` / `Dockerfile` には一切触らない）。

## 機能

- **自動ポモドーロ**: ポモドーロ専用VCに誰かが入った瞬間に開始。作業25分（全員サーバーミュート）→ 休憩5分（解除）を繰り返し、VCが空になったら終了。コマンドは不要
- **残り時間の表示**: 告知チャンネルの**1本のメッセージ**に `<t:UNIX秒:R>` 付きで表示（カウントダウンはDiscord側が行う）
- **終了時刻をVCステータスに表示**: `🍅 作業中 〜01:39` / `☕ 休憩中 〜01:44`
- **`/call end-at`**: 指定時刻に通話を終了（オーナー専用）。5分前・1分前に告知して、時刻になったら全員切断。対象VCのステータスに `⏰ 23:00 に終了` を出す
- **`/pomo status`**: 今のフェーズと残り時間（誰でも）

## セットアップ

```sh
cp .env.example .env   # 値を埋める
docker compose up -d --build
```

### Discord Developer Portal 側

- **Bot → Privileged Gateway Intents**: `SERVER MEMBERS INTENT` を ON にしておくのを推奨
  （VCの在室者は voiceStateUpdate からも取れるので必須ではないが、起動直後にVCへ既に人が居た場合の
  取りこぼしを防げる。`MESSAGE CONTENT INTENT` は使わないので OFF のままでよい）
- 使用するIntentは `Guilds` / `GuildVoiceStates` / `GuildMessages`。いずれも特権Intentではない
- **招待URLのスコープ**: `bot` + `applications.commands`
- **必要な権限**:
  | 権限 | 用途 |
  |---|---|
  | メンバーをミュート (Mute Members) | ポモドーロの必須権限 |
  | メンバーを移動 (Move Members) | `/call end-at` の切断 |
  | メッセージを送信 (Send Messages) | 告知チャンネル |
  | ボイスチャンネルのステータス設定 (Set Voice Channel Status) | 終了時刻の表示。無くても動く（警告ログが出るだけ） |

  ⚠ **「チャンネルの管理 (Manage Channels)」は不要**。VC名を変更する機能は持たない（下記）。
- Botのロールは、**ポモドーロ参加者のロールより上**に置くこと（下だとミュートできない）

## 告知の方針（通知を増やさない）

**1ポモドーロにつき告知メッセージは1本**。フェーズが変わるたびに新規投稿すると、
25分ごとにチャットが告知で埋まるため、最初の1本を**編集して書き換える**。
`<t:...:R>` は編集しても自動カウントダウンが効くので、これで困らない。

```
投稿  🍅 作業開始です！   ← 1本目
編集  ☕ 休憩タイムです！  ← 同じメッセージを書き換え
編集  🍅 作業開始です！
編集  ✅ ポモドーロを終了しました
```

編集に失敗したら（メッセージが消された等）**新規投稿に落ちて機能は止めない**。
終了したらメッセージを手放すので、次のポモドーロは新しい1本を立てる。

出さない通知:

- **「ミュートが残っています」の個別告知は出さない。** 作業開始の告知に毎回
  `-# ⚠ 作業中に抜けるとミュートが残ります…` と書いてあるので周知はそれで足りる
- 終了告知に解除待ちの人を列挙もしない

ただし**ログには必ず残す**（運用者が追えなくなるのは困るため）。
解除待ちは `/pomo status` でも確認できる。

例外的に新規投稿するもの:

- `⚠️ ミュート解除に失敗しました` — 埋もれては困るので常に新規投稿
- `/call` の5分前・1分前・終了 — 気づいてもらうことが目的なので編集では意味がない（1予約につき最大4件）

## VCステータスへの表示（終了時刻）

VC名の下に出る「ステータス」に、今のフェーズと**終了時刻**を出す。

```
ポモドーロ    🍅 作業中 〜01:39   /   ☕ 休憩中 〜01:44
/call end-at  ⏰ 23:00 に終了
```

| | |
|---|---|
| API | `PUT /channels/{id}/voice-status`（discord.js に専用メソッドが無いので REST を直接叩く） |
| 書くタイミング | **フェーズが変わったときだけ**。作業↔休憩の切り替えと、`/call` の予約／解除 |
| 消すタイミング | ポモドーロ終了・`/call` の終了／取消・`SIGTERM`・**起動時**（前回の残骸の掃除）。空文字 `""` を入れると消える |
| 失敗したとき | **警告ログを出すだけ**。機能は止めない |

### ⚠ VCチャンネル名は変更しない（2026-09-22・本人の指示）

以前は「ステータスが使えなければVC名を `🍅作業中` に改名する」フォールバックがあったが、**丸ごと削除した**。

- 改名を戻し損ねると、**サーバーのチャンネル名が壊れたまま残る**
- 改名は**10分に2回**というレート制限がある（短いサイクルに設定すると必ず当たる）
- ステータスにはその制限が無く、空文字で確実に消せる

そのため `DiscordGateway` に `setChannelName` / `getChannelName` は**存在しない**。足さないこと。
`WORK_CHANNEL_NAME` / `BREAK_CHANNEL_NAME` の環境変数も廃止した。
テストのスタブにも改名APIを置いていないので、うっかり復活させると `TypeError` で即座に落ちる。

ステータスが出せなくても、残り時間は告知メッセージの `<t:...:R>` が自動でカウントダウンするので実用上は困らない。

### ⚠ 残り時間を定期更新してはいけない

ステータスには**終了時刻**（`〜01:39`）を書く。「残り13分」のような相対表示を1分ごとに書き換えると、
APIを無駄に叩くうえ、`<t:...:R>` が既にやっていることの二重実装になる。

### 時刻は必ずJST

ステータスは「Botが書いた文字列」がそのまま出るため、コンテナがUTCで動いていると9時間ずれた時刻を堂々と表示してしまう
（compose の `TZ` が無視される事故は実際に起きている — ルートの `CLAUDE.md` を参照）。
そこで `utils/time.js` の **`jstClock()` は `TZ` に依存せず UTC+9 固定で計算する**。JSTに夏時間は無いのでこれで常に正しい。

⚠ ただし `/call end-at 23:00` の**解釈**（`parseEndTime`）は従来どおりローカルTZ依存。
`docker-compose.yaml` の `TZ=Asia/Tokyo` は引き続き必須。

## ⚠ ミュート解除の仕様（重要）

**VCに接続していない相手のサーバーミュートは、Discordの仕様上そもそも解除できない。**

```
PATCH /guilds/{guild}/members/{user}  {"mute": false}
→ 400  {"code": 40032, "message": "Target user is not connected to voice."}
```

つまり「VCを抜けた人をその場で解除する」ことは**不可能**。
そこで **「次にVCに入った瞬間に解除する」** 方式にしている。

| タイミング | 動作 |
|---|---|
| 休憩に入る／VCが空になる／`SIGTERM` | 全員まだ接続中なのでここで解除できる。**成功/失敗を1人ずつログに出す** |
| 誰かがVCを完全に切断 | 解除を試みる → `40032` なら**解除待ち（pendingUnmute）として台帳に残す**。消さない |
| 誰かが**どこかの**VCに入室 | 解除待ちならその場で解除して台帳から削除（ポモドーロ専用VCに限らない） |
| 別のVCへ移動 | 接続が続いているのでその場で解除できる |
| 起動時 | 台帳を読み、接続中の人は解除。未接続の人は**解除待ちのまま保持** |
| `40032` 以外の失敗 | 3回までリトライ → 駄目なら告知チャンネルに `⚠️ ミュート解除に失敗しました` |

台帳は `STATE_DIR/muted-members.json`。**ミュートする前に**書き、解除できて初めて消す。
解除待ちは名前付きボリュームに残るので、コンテナ再作成やクラッシュをまたいでも失われない。

参加者向けには、作業開始の告知に毎回この1行を添えている:

> ⚠ 作業中に抜けるとミュートが残ります。次にVCに入ると自動で解除されます。

解除待ちの人がいるかは `/pomo status` でも確認できる。

### ログの読み方

解除は必ず**結果**が出る。「解除します」だけで結果が出ないことはない（以前それで失敗を見落とした）。

```
[Pomodoro] 解除成功: 2466…（休憩開始）
[Pomodoro] 解除できませんでした: 2466… — VCに接続していないため（Discord仕様 40032）。解除待ちとして台帳に残します。…
[Pomodoro] 休憩開始の解除結果: 解除 2人 / 解除待ち 1人 / 失敗 0人
```
